# Циклический тест реле на Arduino Uno

Отдельный диагностический скетч, не часть протокола Bronkhorst GUI. Основная прошивка TTL/клапанов и прежний ручной тест не изменены. Загрузка этого скетча временно заменяет прошивку на Uno.

## Запуск

1. Перекройте газ аппаратно. Проверку проводите под наблюдением; отключение питания клапана не обязательно закрывает газ. Защита катушки и предохранитель нужны независимо от теста. Не переключайте проводку под напряжением.
2. Оставьте D4 → IN1 существующего правильно подключённого модуля реле. D5 постоянно выключен (HIGH для active-LOW). Не подключайте катушку клапана непосредственно к GPIO. Отключите TTL-кабели ЯМР на время диагностики.
3. Закройте Bronkhorst GUI и другие программы, занимающие COM-порт.
4. Откройте `arduino_relay_cycle_test.ino`, выберите Arduino Uno и загрузите.
5. Откройте Serial Monitor на **115200 baud**. Открытие порта на Uno само может вызвать сброс: дождитесь `BOOT`, затем отправьте **s**.

Реле включается на 2 секунды и выключается на 2 секунды. Один цикл — ON, выдержка, OFF, выдержка. По умолчанию тест заканчивается после 1000 циклов. В начале скетча можно изменить `ON_MS`, `OFF_MS`, `MAX_CYCLES` (0 — без ограничения). Полярность задаёт `ACTIVE_LOW` (по умолчанию `true`).

Команды: **s** — новый тест с цикла 1; **0** — остановка и OFF; **?** — состояние и последний сохранённый этап. При работающем тесте повторное `s` не сбрасывает счётчик. Снятие/подача питания не является безопасным способом перекрыть газ.

## Как найти цикл сбоя

Пример:

```text
[uptime_ms=22000] CYCLE=6 COMMAND OFF (D4 HIGH)
BOOT RELAY_CYCLE_TEST; outputs OFF; automatic restart DISABLED
RESET_CAUSE MCUSR=0x0 UNKNOWN_BOOTLOADER
LAST_CHECKPOINT cycle=6 stage=BEFORE_OFF / OFF_HOLD
```

Это означает: последняя сохранённая операция — отключение реле в цикле 6 либо последующая выдержка OFF. `D4_WRITE_DONE` означает лишь выполнение записи GPIO, не проверку контактов или положения клапана. `CYCLE_COMPLETED` появляется только после всей выдержки OFF. Сохранение производится перед переключением, поэтому это окно сбоя, а не доказательство его физической причины.

После сброса оба реле командуются OFF, автоматического продолжения **нет**. Скопируйте `BOOT`, `RESET_CAUSE`, `LAST_CHECKPOINT` и несколько последних строк перед сбоем. Новый запуск — `s`. Если Windows потеряла USB-порт, откройте его заново: EEPROM сохранит последний корректный этап, но само открытие порта может вызвать ещё один сброс. Начальный OFF при загрузке тоже может переключить ранее включённое реле.

Если порт исчез, но после восстановления нет нового BOOT и uptime не обнулился, это не подтверждённый сброс основного микроконтроллера. Возможен сбой USB-связи. `UNKNOWN_BOOTLOADER` не позволяет определить причину: загрузчик может очищать MCUSR. Watchdog в этом тесте отключён, чтобы не добавлять искусственную причину сброса.

## EEPROM

Используются **байты 0–415 EEPROM**: 32 записи с циклической ротацией, CRC и фиксацией заголовка в конце. Они перезаписывают прежние данные в этой области. Перед загрузкой сохраните её, если другая прошивка хранит там важные настройки. Данные других адресов не изменяются.

Три записи на цикл (перед ON, перед OFF, после выдержки OFF); команда остановки добавляет запись. Ротация уменьшает износ, но ресурс EEPROM конечный: скетч предназначен для диагностики, не для непрерывной эксплуатации. Запись немного увеличивает промежуток между циклами. При сбое во время записи может сохраниться предыдущая корректная запись, а не последний этап; сильная помеха может повредить данные. Это не аварийный регистратор с гарантией сохранности.

После диагностики верните `../arduino_nmr_ttl/arduino_nmr_ttl.ino` для работы с GUI и ЯМР.
