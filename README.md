# Bronkhorst EL-FLOW Prestige: автоматическое подключение и программа эксперимента

`bronkhorst_gui.py` показывает все подключённые USB-COM интерфейсы, а затем подключает EL-FLOW Prestige по выбранному оператором COM-порту через штатный Bronkhorst FLOW-BUS/ProPar протокол. Прибор идентифицируется серийным номером, моделью и текущим потоком, поэтому переназначение Windows с `COM3` на `COM7` не требует ручной правки программы.

Поиск выполняется только командами **чтения** ProPar. Запись уставок возможна после включения управления. Старт автоматического плана требует подтверждения; ручные кнопки установки и обнуления отправляют команды сразу.

Окно разделено на вкладки **Подключение**, **Параметры газа**, **Эксперимент** и **Консоль**. Консоль содержит журнал подключений, команд, этапов эксперимента и ошибок с временем события; сохраняются последние 2000 строк в памяти. При повторяющейся ошибке связи внутренний сеанс ProPar пересоздаётся.

Галочка **Короткие логи** на вкладке «Консоль» скрывает технический обмен,
служебные команды и дублирующие подтверждения. Этапы опыта, номера спектров,
подтверждения записи, реле, восстановление, ошибки и сбросы остаются видны.
Без галочки отображаются все сообщения (режим по умолчанию). Переключение
перестраивает уже накопленный журнал, не удаляя скрытые сообщения из последних
2000 записей. «Последние события» использует тот же фильтр. «Копировать» копирует
текущий вид; для диагностики снимите галочку и скопируйте полный журнал.
«Очистить» удаляет историю в обоих режимах. Фильтр не влияет на работу приборов.

> Это не система противоаварийной защиты. Для H₂ обязательны независимые отсечные клапаны, защита давления, проверка герметичности, безопасный сброс и аварийное отключение. Закрытие GUI, USB и Modbus не являются надёжным способом остановить опасный поток.

## Запуск

В терминале VS Code:

```powershell
.\.venv\Scripts\python.exe bronkhorst_gui.py --config config.json
```

Если окружение ещё не создавалось:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

В VS Code выберите `.venv\Scripts\python.exe` через `Python: Select Interpreter`.

## Первый запуск с приборами

1. Отключите подачу газа и подключите USB–RS485/RS232 адаптеры и MFC.
2. В `config.json` задайте скорость, чётность и стоп-биты, совпадающие с MFC. Программа не может безопасно подбирать их автоматически.
3. Укажите скорость с заводской наклейки прибора (`38400` — типичное значение для RS232 ProPar). Стандартное прямое RS232-подключение использует локальный адрес ProPar автоматически.
4. На вкладке **Подключение** выберите `COM5` в списке и нажмите `Подключить`, затем так же подключите второй MFC, например `COM6`. Подключённые устройства появятся в таблице с серийным номером, текущим COM-портом, диапазоном и измеренным расходом.
5. Один раз для каждого серийного номера выберите роль `H2` или `Alkene` и нажмите `Сохранить роль`. Роль сохраняется в `config.json`, поэтому после переподключения USB определяется снова по серийному номеру, а не по COM-порту.
6. Для каждого MFC выберите `Чтение потока` или `Управление потоком` и нажмите `Сохранить режим`. В режиме чтения программа показывает расход и уставку, но блокирует отправку новой уставки. В режиме выставления доступны ручные команды; автоматический план запускается, только если оба канала H₂ и алкена выбраны в этом режиме.

На четвёртой вкладке **Консоль** журнал фиксирует время нажатия кнопки, открытие COM, паспортный ответ ProPar, повторное создание сеанса, команды уставок и ошибки доступа. Обновление списка COM не открывает последовательные порты и не мешает FlowSuite или стороннему монитору.

Автоматическое определение подтверждает, что устройство отвечает как Bronkhorst по используемым регистрам. Оно не способно физически узнать, какой баллон подключён к конкретной линии: роль H₂/алкен должен назначить оператор.

## Газовый набор и условия для каждого MFC

EL-FLOW Prestige содержит официальную встроенную Bronkhorst-базу газов; это не таблица, рассчитанная приложением. GUI читает у каждого серийного номера активный `fluid set`: его номер, название газа, заданные входное и выходное давление, температуру и опорное давление объёмной единицы.

Для смены газа выберите **Профиль газа** (0–7), введите ожидаемое имя газа и нажмите `Активировать профиль`. Это переключает только уже преднастроенный в приборе набор; затем программа читает фактическое имя газа обратно из MFC. Если оно не совпадает с сохранённым ожидаемым именем, появляется `GAS PROFILE MISMATCH` и поток начинать нельзя.

Кнопка `Сохранить условия газа` сохраняет и передаёт в активный набор условия `inlet`, `outlet`, `temperature` и `reference`. Давления вводятся в **bar(a)**, то есть для показаний манометра в bar(g) необходимо прибавить атмосферное давление. Эти поля являются условиями модели газа и перевода массового расхода в объёмный, а не заменой датчика реального давления или заводской метрологической калибровки.

Профили, подтверждённые оператором, сохраняются в `config.json` отдельно для каждого серийного номера и слота. Не меняйте заводские коэффициенты датчика, диапазон или параметры клапана из этого приложения. Газовая база и переключение fluid set описаны Bronkhorst в [списке встроенных газов](https://www.bronkhorst.com/en-us/service-support/faq-en/installation/which-gases-are-embedded-in-the-el-flow-prestige-mass-flow-meter-controller/?pdf=true) и [руководстве EL-FLOW Prestige](https://products.bronkhorst.com/media/dtrhzjhu/917084-manual-el-flow-prestige.pdf).

## План эксперимента

Если подключён **один MFC**, он получает весь заданный поток, а поле соотношения скрыто. Назначать роль газа для одиночного прибора не требуется. При **двух MFC** используются роли «Водород» и «Алкен», и общий поток делится по соотношению. В обоих случаях приборы должны быть в режиме «Управление потоком».

Настройки прокручиваются, а кнопки «Запустить» и «Стоп · поток в ноль» закреплены внизу вкладки. Во время выполнения плана его поля и выбор режима заблокированы. Измеренный расход в ручных карточках отображается отдельно от уставки, считанной из прибора.

Кнопка **Дизайн эксперимента ↗** открывает отдельное окно. В нём задаются:

- `Начальный поток`, `Конечный поток`, `Шаг потока` — суммарный поток;
- `H₂ : алкен` — фиксированное отношение;
- `t1, с` — задержка после изменения расхода до запуска спектра №1 (прежняя «Выдержка»);
- `t2, с` — задержка после подтверждения спектра №1 до переключения выбранных реле;
- `t3, с` — задержка после переключения выбранных реле до запуска спектра №2;
- `t4, с` — задержка после подтверждения спектра №2 до завершения точки и перехода к следующей.

### Произвольные точки и серия на одном потоке

В поле **«Задание точек»** можно выбрать:

- **«Диапазон с шагом»** — прежний режим с начальным/конечным потоком и шагом.
- **«Список потоков»** — введите значения по порядку, например `100 110 110 110 120`. Никакой сортировки или удаления повторов: получится ровно пять отдельных точек. Можно уменьшать поток, возвращаться к предыдущему или включать ноль.

Числа разделяются пробелами или `;`, десятичный разделитель — точка или запятая (`10.5 11,5 10`). Запятая **не** разделяет соседние значения списка. Для двух MFC это суммарные потоки, делящиеся в отношении H₂ : алкен; один MFC получает весь поток.

**«Повтор каждой точки»** задаёт полное число её последовательных выполнений (1 — без дополнительных повторов). Например, список `10 20` и повтор 3 дают `10 10 10 20 20 20`, не три прохода всего списка. Повтор работает и для диапазона с шагом.

Для проверки стабильности/деградации катализатора: выберите **«Список потоков»**, введите один поток, например `100`, и задайте **30** повторов. Получится 30 отдельных циклов с тем же потоком. В каждом заново выполняются t1–t4, переключения реле по выбранному порядку и **два** спектра с отдельными TTL-подтверждениями: итого **60 спектров**, а не 30. Само изменение активности катализатора программа не рассчитывает — это серия измерений для последующего анализа спектров.

Нажмите **«Проверить план»**, чтобы увидеть все пронумерованные точки и число спектров. График сохраняет порядок и повторы, хотя соседние одинаковые потоки выглядят как одна длинная горизонтальная линия. Для каждой точки проверяются диапазоны MFC, включая превышения в начале или середине списка. Числа должны быть конечными и неотрицательными; не более 10 000 точек с учётом повторов. Во время опыта источник точек, список и повторы заблокированы.

**«Сохранить дизайн»** сохраняет источник (`experiment.plan_mode`: `range`/`custom`), текст списка (`custom_flows`) и повтор (`point_repeats`) вместе с остальными настройками. Старые конфиги без этих полей продолжают задавать диапазон с одним выполнением каждой точки. Прошивка Arduino не меняется.

Опция **«Обратный порядок реле: сначала ON, после t2 — OFF»** в дизайне меняет только последовательность автоматического режима с клапанами:

- Выключена (по умолчанию): до первого спектра OFF, после t2 ON, после t4 OFF.
- Включена: до первого спектра ON, после t2 OFF; после полной t4 ON возвращается только для следующей точки. После последней точки реле остаются OFF — короткого лишнего ON нет.

Выбор сохраняется как `experiment.relay_initial_on`, отражается на схеме и в подтверждении запуска. Полярность Arduino остаётся прежней: LOW = ON, HIGH = OFF; ручные кнопки, проверочный импульс, стартовые уровни прошивки и аварийное выключение не инвертируются. После окончания, ошибки или «Стоп» всегда запрашивается OFF, а не начальное состояние цикла. ON/OFF не подтверждает физическое положение клапана.

При восстановлении связи на t1 сначала подтверждается OFF; для обратного порядка затем заново подтверждается ON **до** повторной подачи расхода и полной выдержки t1. Неудача ON останавливает эксперимент. На прерванной t4 сохраняются OFF и предупреждение; ON допускается уже на следующей точке. Сбой переключения сразу после t2 по-прежнему завершает опыт без автоматического повтора спектра или переключения.

Задержки допускают ноль и десятичную запятую. Они не включают длительность записи спектров: каждый спектр ожидает собственный ответный TTL, а тайм-аут Arduino применяется отдельно к каждой записи. Окно содержит схему двух измерений и положения клапана; нажатие на t1–t4 переводит фокус в соответствующее поле. Схема не в масштабе времени, активный этап выделяется во время выполнения. Поля можно заполнить до подключения MFC. **Сохранить дизайн** записывает диапазон, шаг, соотношение и t1–t4 в раздел `experiment` конфигурации. Проверка диапазонов и запуска по-прежнему требует подключённых MFC. При изменении дизайна старая таблица точек очищается; перед запуском план проверяется заново.

После `Проверить план` вкладка **Эксперимент** показывает таблицу точек с прокруткой. Кнопка `Открыть график` открывает масштабируемое окно графика уставок H₂/алкена, текущих измеренных расходов и активной экспериментальной точки. Ось X показывает сумму задержек t1–t4; длительность записи ЯМР неизвестна заранее и не включена. Если все задержки равны нулю, график показывает точки с равными интервалами. Фактически уставки удерживаются в течение всего цикла, включая обе записи ЯМР.

Вверху вкладки **Эксперимент** выбирается один из трёх режимов: **Ручной**, **Авто + ЯМР**, **Авто + ЯМР + клапаны**. В обоих автоматических режимах доступны таблица точек и график; запуск требует готовую Arduino, `Разрешить подачу газа` и режим `Управление потоком` у каналов плана. Каждый автоматический цикл записывает два спектра. Режим без клапанов пропускает только переключение реле, сохраняя все четыре задержки.

В ручном режиме для каждого подключённого MFC создаётся отдельная карточка в вертикальном списке с прокруткой: серийный номер, COM, газ в приборе, режим MFC, текущий измеренный поток, прочитанная из прибора уставка и поле ввода нового потока. При отсутствии приборов карточек нет. Обновление измерений не меняет вводимый текст. В карточке MFC с режимом `Чтение потока` поле и кнопки недоступны. Можно управлять и каналом с ролью `Other`. В ручном режиме переключатель `Разрешить подачу газа` скрыт: кнопки `Установить`, `Ноль` и Enter в поле отправляют команду сразу для MFC с режимом `Управление потоком`. Нулевая уставка не подменяет измеренное значение нулём: оба показания выводятся независимо. Пока выполняется автоматический план, переключение режима и редактирование дизайна заблокированы; окно дизайна можно открыть для просмотра. Перед возвращением к автоматическому режиму вручную заданные ненулевые уставки нужно обнулить.

Например, значения потоков `10`, `150`, шага `10` и отношения `4` образуют 15 точек: 10, 20, …, 150 и 30 спектров. Для каждой точки рассчитываются `F_H2 = 0.8 × F_total` и `F_alkene = 0.2 × F_total`. При t1=60 и остальных задержках 0 расход удерживается не менее 60 секунд плюс время двух записей ЯМР. До старта приложение проверит, что конечная точка укладывается в capacity обнаруженных устройств и что единицы у них совпадают.

Нажмите `Проверить план`, затем включите `Разрешить подачу газа` и выберите `Запустить`. При обычном завершении и при нажатии `STOP` программа отправляет нулевые уставки H₂ и алкену. Если связь с прибором пропала, запись нулевой уставки не гарантирована — именно поэтому требуются аппаратные защиты.

В «Консоли» можно скопировать или очистить журнал. После ответа `TRIGGERED` появляется сообщение об отправке TTL, а после `NMR_DONE` — о приёме ответного TTL. Отправка одной команды `TRIGGER` ещё не считается подтверждением физического импульса.

## Авто + ЯМР: два спектра и TTL-подтверждение

### Проверка реле перед опытом

Вверху вкладки **Эксперимент** выберите одно реле (D4/IN1 или D5/IN2) либо оба,
подключите Arduino и нажмите **Проверить реле (1 с)**. Расходомеры и разрешение
подачи газа для этой проверки не нужны. GUI сначала подтверждает OFF, затем
включает выбранные каналы на одну секунду и автоматически запрашивает OFF.
**Выключить все** прерывает проверку или отдельно снимает управление с обоих
каналов. Во время проверки нельзя менять каналы/режим, переподключать Arduino
или запускать эксперимент; во время эксперимента ручные кнопки проверки недоступны.

Ответы Arduino и ошибки отображаются под кнопками и в консоли. GUI подтверждает
команды выходам D4/D5, но не измеряет контакты реле: щелчок и переключение COM–NO/NC
проверьте самостоятельно, первоначально без подключённого питания 24 В клапанов.
При закрытии окна GUI дожидается завершения проверки и команды OFF.

Используется уже описанная ниже прошивка с поддержкой `RELAY_MASK`; отдельный
тестовый скетч для проверки из GUI не нужен.

На вкладке **Эксперимент** выберите **Авто + ЯМР** или **Авто + ЯМР + клапаны**, отдельный COM-порт Arduino, baudrate и тайм-аут одной записи, затем нажмите `Подключить Arduino`. Порт Arduino не должен быть портом Bronkhorst MFC. Настройте потоки и задержки в окне дизайна.

Последовательность одной точки (без обратного порядка):

1. Программа выставляет расход и ждёт t1.
2. Спектр №1: команда `TRIGGER <run-id>-s1 <point>`, подтверждение `TRIGGERED`, запись ЯМР, ответный TTL и совпадающий `NMR_DONE`.
3. Задержка t2, затем команда ON выбранным реле D4/D5 и ожидание подтверждения (только в режиме с клапанами).
4. Задержка t3, затем спектр №2 по той же последовательности с идентификатором `<run-id>-s2`.
5. Задержка t4, затем команда OFF обоим реле и ожидание подтверждения, завершение точки и переход к следующему расходу.

Уставки MFC не меняются между спектрами. Точка считается завершённой после обоих подтверждений и t4. Идентификаторы спектров различаются, поэтому старые Serial-сообщения от первого спектра не подтверждают второй. При тайм-ауте, `ERROR` или остановке план прекращается и запрашиваются нулевые уставки управляемых каналов; посторонние идентификаторы игнорируются.

**Выбор реле:** на вкладке «Эксперимент» в разделе Arduino доступны «Одно реле №1 · D4 → IN1», «Одно реле №2 · D5 → IN2» и «Два реле». По умолчанию активируется только реле №1 (D4). В обычном порядке после t2 выбранные выходы переходят в LOW (ON), после t4 — HIGH (OFF); обратный порядок задаётся в дизайне. Неиспользуемый выход всегда HIGH. При остановке и потере связи все реле OFF (HIGH). Нажмите «Сохранить выбор»: настройка записывается в `experiment.relay_mask`. Во время опыта выбор недоступен. Загрузите обновлённый `arduino_nmr_ttl/arduino_nmr_ttl.ino`: GUI проверяет поддержку `RELAY_MASK`, чтобы старая прошивка не включила оба реле вместо одного. Положение самого клапана определяется его типом NO/NC; GUI подтверждает уровни выходов Arduino. Подробности подключения и протокола — в `arduino_nmr_ttl/README.md`.

На старте платы прошивка должна один раз вывести строку `READY`. Строки Serial заканчиваются переводом строки и используют ASCII. `run-id` и номер точки нельзя игнорировать: Arduino должен хранить активную пару после `TRIGGER`, принимать возвратный TTL только в состоянии ожидания этой пары, а после `NMR_DONE` перейти в `IDLE`. Практически полезны фильтрация дребезга/ложных фронтов, минимальная допустимая задержка после исходящего TTL и ответ `ERROR <run-id> <point> <reason>` при внутренней ошибке. Эталонная прошивка находится в [`arduino_nmr_ttl/arduino_nmr_ttl.ino`](arduino_nmr_ttl/arduino_nmr_ttl.ino); перед загрузкой настройте пины, уровни TTL, развязку и логику под вашу консоль.

Возвратный TTL — обязательная обратная связь, но не является доказательством качества спектра или правильности интеграции: это подтверждение того, что консоль отправила предусмотренный импульс. Перед работой на газовой линии проверьте протокол на макете/безопасной инертной подаче и убедитесь осциллографом, что уровни TTL и земли совместимы.

## Восстановление Arduino на t1, t4 и завершающем OFF

В окне **Дизайн эксперимента → Потеря связи с Arduino** включите
**Восстанавливать Arduino на t1, t4 и завершающем OFF**. По умолчанию опция
выключена и применяется только в режиме **Авто + ЯМР + клапаны**.
Там же задаются **попыток на один цикл (точку)** (1–100, по умолчанию 3)
и **пауза перед каждой попыткой** (0,1–60 с, по умолчанию 1 с).
Настройки сохраняются кнопкой «Сохранить дизайн» и блокируются во время опыта.
В конфигурации используются `experiment.recover_after_off` (историческое имя
общей галочки), `experiment.recovery_attempts` и `experiment.recovery_interval_s`.

После сброса/потери связи на разрешённом этапе программа сначала запрашивает
нулевую уставку всех управляемых MFC, затем закрывает старый порт и пытается
подключиться к **тому же COM-порту**. Каждая попытка пишет в консоль
«Пробую подключиться к Arduino…», номер цикла и номер попытки. **Перед каждой
попыткой, включая первую после обрыва, выдерживается полная заданная пауза**;
ожидание тоже отображается в консоли. Каждое открытие
получает время на READY (`arduino.startup_timeout_s`), чтобы повторным открытием
не мешать загрузке Uno. Нужны READY, RELAY_MASK, подтверждение OFF обоих реле,
ещё 1 с контроля связи и свежее подтверждение OFF.

- **Сбой на t1:** после восстановления снова задаётся расход текущей точки и
  полностью запускается t1. TTL ещё не отправлялся, спектры не дублируются.
- **Сбой на t4:** оба спектра уже подтверждены. Реле остаются OFF, газ повторно
  на этой точке не подаётся, остаток t4 не возобновляется. Точка помечается
  **«Завершена, t4 прервана»**, предупреждение остаётся в консоли, таблице и
  итоговом сообщении. После этого начинается следующая точка.
- **Сбой на завершающем OFF:** сохраняется контроль связи в течение 1 с после
  OFF и свежий ACK обоих реле; восстановление завершает текущую точку без
  повторного запуска спектров. На последней точке опыт просто завершается.

Счётчик попыток **отдельный для каждой точки/цикла**, включая успешные подключения.
В начале следующей точки снова доступны все заданные попытки (по умолчанию 3).
Если в одной точке восстановление заняло две попытки из трёх, на следующий
обрыв в этой же точке останется одна. Когда попытки исчерпаны, опыт останавливается. «Стоп» отменяет
ожидание, не допускает повторной подачи расхода и следующей точки. Неудача
установки нуля MFC, неправильный ACK/прошивка, обрыв на t2/t3, ON или во время
спектра по-прежнему останавливают опыт без автоматического продолжения.
Прошивка не меняется: используется текущая версия с RELAY_MASK.

Это механизм ограниченного восстановления связи, **не исправление аппаратных
помех**. Подтверждение нулевой уставки и OFF не доказывает физическое прекращение
потока или положение клапана. Защита катушки, аппаратный запорный клапан и
испытание без подачи газа по-прежнему необходимы.

## Конфигурация обнаружения

```json
"discovery": {
  "scan_interval_s": 2.0,
  "probe_timeout_s": 0.12,
  "ports": [],
  "include_non_usb": false,
  "slave_ids": [1, 2]
}
```

Для Arduino настройки сохраняются отдельно и могут быть заданы заранее:

```json
"arduino": {
  "port": "COM9",
  "baudrate": 115200,
  "spectrum_timeout_s": 180,
  "startup_timeout_s": 8
}
```

- Пустой `ports` сканирует USB-последовательные устройства раз в `scan_interval_s` секунд.
- Для встроенного или не-USB последовательного порта добавьте, например, `"ports": ["COM7"]` либо установите `include_non_usb: true`.
- `probe_timeout_s` не следует задавать ниже `0.4`; для двух MFC через USB-хаб рекомендуется `0.5` с.
- `slave_ids` сохранён для будущего режима RS485 Modbus; при прямом EL-FLOW Prestige RS232/ProPar он не используется.

EL-FLOW Prestige поддерживает Modbus на соответствующем RS485/опциональном интерфейсе, но его обычный USB–RS232 путь использует FLOW-BUS/ProPar. Именно этот интерфейс использует программа. [Руководство EL-FLOW Prestige](https://products.bronkhorst.com/media/dtrhzjhu/917084-manual-el-flow-prestige.pdf) и [документация ProPar](https://bronkhorst-propar.readthedocs.io/en/latest/).

## Ручное управление клапанами

На вкладке «Эксперимент» выберите **«Ручной»**. В блоке **«Клапаны · ручное управление»** выберите COM-порт Arduino и подключитесь. Расходомеры для управления реле не обязательны. Нужна основная прошивка `arduino_nmr_ttl/arduino_nmr_ttl.ino` с `RELAY_MASK`, не отдельный диагностический скетч реле.

- Выбор канала: №1/D4 → IN1, №2/D5 → IN2 или оба. Выбор общий с дизайном эксперимента; для сохранения между запусками используйте «Сохранить выбор» в дизайне.
- **«Включить · ON»** включает выбранные реле и оставляет их включёнными; остальные выключены. Это не импульс проверки на 1 с.
- **«Выключить все · OFF»** отправляет OFF обоим реле. При незавершённом ON запрашивает выключение после текущей команды.
- Статус и консоль показывают подтверждённые Arduino выходы D4/D5. Это не показания датчиков положения клапана. ON/OFF относится к реле: нормально открытый и нормально закрытый клапаны реагируют на питание по-разному.

Ручная команда не меняет уставки MFC и не отправляет TTL. Пока включённые реле не получили подтверждённый OFF, смена режима, проверочный импульс и запуск автоматического эксперимента заблокированы. При потере связи статус становится неподтверждённым; переподключение не восстанавливает ON автоматически. Сначала отправьте OFF. Arduino продолжает получать KEEPALIVE; при потере связи действует существующий аппаратно-программный тайм-аут прошивки. Закрытие GUI запрашивает OFF, но не гарантирует физическое прекращение потока.

Это управление оборудованием, а не устранение помех: защита катушки и аппаратное перекрытие газа по-прежнему нужны.

## Проверка без оборудования

Для визуальной проверки есть отдельный офлайн-предпросмотр:

```powershell
.\.venv\Scripts\python.exe preview_gui.py --mode automatic-arduino-valves --demo
```

Окно явно помечено **«ОФЛАЙН»**. Рабочие потоки Arduino/MFC не запускаются, команды и сохранение конфигурации заменены имитацией. `--demo` показывает синтетические данные двух MFC и план; без флага открывается пустой интерфейс. Клавиши F6/F7/F8 переключают размеры 780×540, 1180×820 и 1700×900 только в предпросмотре. Это не проверка работы оборудования.

Компоновка: выбор режима сверху, компактная колонка Arduino и плана слева, показания и точки справа, запуск/стоп в закреплённой нижней панели. Параметры связи и распиновка сворачиваются; автоматическая настройка реле видна только в режиме с клапанами. Ручные кнопки реле остаются в ручном режиме. Полная схема цикла и редактирование — в отдельном окне дизайна.

Копия `bronkhorst_gui.py` и `bronkhorst_ui.py` перед этой переработкой сохранена в локальной папке `.ui_backups/before_compact_layout_2026-10-28_c3568938/` (исключена из Git).

```powershell
.\.venv\Scripts\python.exe -m unittest -v
```

Тесты проверяют расчёт расхода, ручные команды MFC, обмен TTL, последовательность двух спектров, четыре задержки, остановку на любом этапе, подтверждение реле и обработку потери связи и сохранение дизайна. Они не заменяют испытание с реальными MFC на безопасной инертной линии.
